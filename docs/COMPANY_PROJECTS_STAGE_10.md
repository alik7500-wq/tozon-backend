## Изолированный запуск

Новая команда npm run pilot:start запускает src/pilot/server.js. До импорта клиентов проверяет явный PROJECT_WORKSPACE_PILOT_CONFIRM, NODE_ENV=production, точный тестовый SUPABASE_URL (HTTPS, без произвольного пути/учётных данных), FRONTEND_ORIGIN тестового сайта, JWT_SECRET и серверный ключ. Legacy JWT-ключ должен иметь ref теста и role=service_role. Opaque sb_secret ключи проверяются самим Supabase на точном тестовом хосте. Перед listen делается чтение company_projects; при неверных ключах/недоступной БД запуск завершается ошибкой без вывода секрета.

Используется отдельное Express-приложение. Только /api/auth, /api/company-projects, /api/project-workspace и /api/health; работают прежние проверки пользователя/проектных прав, Origin, файлов и команд. Общие uploads, старые финансовые API, интеграционные вебхуки, отправка SMS, внутренние cron endpoints и Telegram-бот не подключаются. Нет импорта production app/server, нет фонового опроса. Внутренние напоминания формируются при разрешённом чтении раздела.

Это новая тестовая конфигурация, а не полная замена прежней демонстрационной CRM. Старые тестовые экраны и AI-сканер не обслуживаются этим API.

## Интерфейс пилота

VITE_PROJECT_WORKSPACE_PILOT=true включает отдельный интерфейс: вход, административный реестр проектов либо рабочее пространство проектного сотрудника. Общий MainLayout, глобальные уведомления и страницы старой CRM не монтируются. Сборка разрешена только на точном тестовом origin с точным тестовым API; отсутствующий API не приводит к запросам production. Проектный marker проверяется прежде ADMIN-названия роли. Режим выключен по умолчанию и не меняет обычный production интерфейс.

Секреты JWT_SECRET, SUPABASE_SERVICE_ROLE_KEY и другие существующие переменные в YAML не записаны и должны сохраниться. Непроектные env vars не используются новым минимальным API. Точный список изменений и отсутствие новых платных ресурсов нужно проверить по результату plan до approve.

Новые флаги дают возможность проверять тестовые операции/документы, но не создают пользователей или проектные назначения. В тестовой БД постоянных назначений пока нет. Понадобятся ограниченные синтетические фикстуры/вход, действующий тестовый бланк и фактическая проверка Storage/печати. Реальные паспортные файлы и рабочие договоры в тест не копируются.
