# Этап 8 — внутренние напоминания по проекту

В пилотном пространстве добавлен отдельный раздел «Напоминания» о предстоящих и просроченных платежах. Это личные записи сотрудников проекта, не SMS и не общий журнал уведомлений. Настройки управляются администратором компании отдельно для каждого проекта; по умолчанию отключены. Изменения настроек имеют собственную версию и неизменяемую через API историю.

## Правила доступа и отбора

Нужны одновременно deals.view и finance.payments, активный пользователь с company.project-only, активное назначение и включённый пилотный профиль. Проверяются актуальные права в БД при каждом чтении и отметке. ADMIN в проектной учётной записи не даёт доступа к настройкам компании. Администратор с access.v2 должен иметь settings.view/manage и users.view/manage.

Учитываются только подписанные договоры своего проекта, собственные клиент и ЖК, действующая иерархия помещений и неоплаченные строки графика. Даты ограничены выбранным началом задолженности и горизонтом 0–30 дней. Будущая начальная дата при включении запрещена. Время определяется по Asia/Dushanbe. Повторный запуск не создаёт дубликаты; переход к просрочке создаёт отдельное событие, прежнее скрывается. Оплата, отмена графика/договора, изменение даты/принадлежности, отзыв прав или отключение настройки немедленно исключают запись из серверной выдачи. История не удаляется.

Получатель видит номер договора, клиента, помещение, срок, остаток, валюту, вид события и личную отметку прочтения. Телефоны и паспортные файлы в выдачу не включены. Отметка прочтения идемпотентна и не требует права финансовой записи. Чужой ID возвращает 404. Таблицы закрыты RLS и отзывом grants для браузерных ролей; функции доступны только service_role и работают как SECURITY INVOKER.

## API и флаги

- COMPANY_PROJECTS_ENABLED=true открывает прежний реестр настроек. GET/PUT /api/company-projects/:id/reminders работают с отдельной версией настроек; конфликт версии — 409.
- PROJECT_WORKSPACE_ENABLED=true и PROJECT_INTERNAL_REMINDERS_ENABLED=true требуются для нового API. Сохраняется проверка точного тестового Supabase URL. В остальных средах пилот закрыт.
- GET /api/project-workspace/:project/reminders и POST /api/project-workspace/:project/reminders/:id/read проверяют серверного пользователя. Cookie-записи требуют точный FRONTEND_ORIGIN. Подмены actor и лишние поля отвергаются.
- VITE_PROJECT_INTERNAL_REMINDERS_ENABLED=true показывает настройки и раздел интерфейса. Клиентский флаг не предоставляет прав API.
- Чтение раздела обновляет его очередь. Отдельный POST /api/internal/project-reminders/run обновляет включённые проекты под существующим SMS_SCHEDULER_INTERNAL_TOKEN, не требуя включения SMS-детектора. Общего исключения для /internal нет. CRM-cookie сохраняет проверку проектной границы. Старый scheduler также может обновлять внутренние напоминания после своего штатного запуска.

Расписание вызова нового внутреннего endpoint в хостинге ещё не создано. Постоянные настройки, назначения и флаги работающих сервисов не изменены. SMS, Telegram и Sheets этим этапом не включаются.
