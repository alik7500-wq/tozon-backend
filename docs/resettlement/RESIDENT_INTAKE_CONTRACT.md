# TOZON CRM — оформление жителя без печати договора

## Требование
Кнопка «Оформить» сохраняет сделку переселения и график рассрочки. Договор оформляется государственным нотариусом; CRM не генерирует договор.

## Текущее состояние (проверено по main)
- В DealWizardModal.jsx есть ввод квартиры, площади, цены, срока и даты первого платежа, а также предварительный график.
- POST /resettlements требует уже существующий deal_id для каждой квартиры; не создаёт сделку.
- POST /resettlements/:id/sign-deal требует утверждённое распределение, совпадение суммы сделки с распределением и реквизиты подписанного договора; атомарно переводит RESERVED → SIGNED, квартиру RESERVED → SOLD.
- Единого атомарного API «создать жителя + график + резервировать квартиру» пока нет.

## Целевое поведение
1. Оператор выбирает квартиру, существующего покупателя, указывает площадь старого жилья, компенсируемую и платную площадь, цену USD/м², срок и дату первого платежа.
2. Сервер проверяет доступ ADMIN/DIRECTOR, принадлежность квартиры проекту, уникальность связи, статус квартиры, положительность и точность сумм, отсутствие повторной операции, согласованность площадей.
3. В одной транзакции создаёт RESERVED-сделку с суммой ТОЛЬКО платной площади, запись переселения и платежный график; блокирует квартиру от повторной продажи.
4. Сохраняет статус типа сделки RESETTLEMENT («Житель»), а не подменяет допустимые значения inventory status.
5. При предъявлении нотариального документа и подтверждении согласованных сумм — существующий атомарный signing workflow переводит RESERVED → SIGNED, квартиру → SOLD. До нотариуса SOLD запрещён.
6. Оплаты отражаются только по реально зарегистрированным приходным документам; создание графика не создаёт ПКО и не меняет кассу.
7. Действующие подписанные договоры, платежи, распределения и утверждённые дела не изменяются автоматически.

## Контракт для реализации
POST /resettlements/intake (НОВЫЙ, пока не реализован)
Body: {project_id, unit_id, lead_id, original_home_area_x100, compensated_area_x100, paid_area_x100, price_per_m2_minor, installment_months, first_payment_date, legal_basis_ref, idempotency_key}
Success 201: {data:{case_id,deal_id,unit_status:"RESERVED",deal_status:"RESERVED",payable_total_minor,schedule:[{due_date,amount_minor}]}}
Errors: 400 INVALID_INPUT; 403 WRITE_DENIED; 409 UNIT_UNAVAILABLE | AREA_MISMATCH | DUPLICATE_INTAKE; 503 UNAVAILABLE.
POST /resettlements/:id/sign-deal — существующий API, использовать только после нотариального документа, согласования суммы и approve-allocation.

## Критерии приёмки
- Повторный запрос с тем же idempotency_key не создаёт вторую сделку.
- Ошибка в середине операции откатывает все записи.
- Сумма графика в центах равна payable_total_minor, включая округление последнего платежа.
- На границе месяцев даты не перескакивают.
- Компенсационная площадь не входит в выручку и долг.
- Нет печати договора, автоматического ПКО или автоматического SOLD до подписания.
- Существующий кейс квартиры 16/17 не переписывается.
- Проверки RLS/RBAC, конкурентных бронирований и аудит действий обязательны.

## Ограничение
Это спецификация, а не реализованный endpoint. Не считать функцию работающей до SQL-миграции, backend API, frontend integration и проверки на тестовой базе.
