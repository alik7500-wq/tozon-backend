# Этап 9 — проверка подготовки проекта перед пилотом

В карточку «Настройки → Проекты компании» добавлена кнопка «Проверить готовность проекта». Проверка читает только сохранённое состояние; при несохранённых изменениях кнопка недоступна. Результат другого проекта/версии очищается, поздний ответ игнорируется. Результат не является разрешением на запуск и не меняет ни одного назначения, документа, кассы или склада.

## Проверяемые условия

- ФИО директора объекта и основание полномочий заполнены.
- Указаны минимум два партнёра с суммой долей 100%. Фактическая договорённость 50/50 и личности требуют ручного подтверждения; программа их не выдумывает.
- Привязан хотя бы один действующий ЖК, архивные ЖК выявляются отдельно.
- Есть состав сотрудников; у каждого активная учётная запись, marker company.project-only, включены пилотный профиль и доступ к этому проекту, задан хотя бы один раздел.
- Права записи согласованы с необходимым чтением; название роли не даёт прав автоматически.
- Для финансовых/складских разделов есть действующие собственные касса/склад.
- У договоров этого проекта либо его ЖК совпадают явный company_project_id, принадлежность помещения и клиента. Выявляются непривязанные договоры и связанные с ними поступления/расходы из чужих либо непривязанных касс. Исторические отменённые записи тоже требуют классификации.
- При праве печати проверяется наличие активных CONTRACT/SCHEDULE бланков RU/TJ своего ЖК либо общего scope '*', а также private bucket. Содержимое Word и правильность юридического текста эта проверка не подтверждает. Отсутствующий bucket можно создать при первой разрешённой тестовой загрузке; публичный недопустим.

Статус configuration_ready означает только заполнение этих технических условий. production_ready всегда false: отдельно обязательны реальные роли/доли, утверждённые бланки, печать/загрузка в браузере, разбор старого учёта и внешних интеграций. Непривязанные расходы без договора, взаиморасчёты, общие клиенты, бартер, подотчёт, себестоимость и сторонние публичные файлы не классифицируются автоматически.

## Сервер

GET /api/company-projects/:id/readiness под общим флагом COMPANY_PROJECTS_ENABLED. Нужен действующий администратор компании с правами настройки и персонала. Дополнительно действует точная проверка тестовой среды PROJECT_WORKSPACE_ENABLED и тестового Supabase hostname. CRM-cookie с чужим Origin запрещён. Параметры actor/контекст/лишние query-поля отвергаются. Проектный ADMIN не может обращаться к этой проверке.

RPC read_company_project_readiness работает SECURITY INVOKER и закрыт для PUBLIC/anon/authenticated. Проверка актуальных прав администратора повторяется в БД. Один SQL-запрос собирает связанные счётчики без ограничения REST в 1000 строк. Бланки и их файлы не выгружаются; HTTP возвращает только список условий, статусы, действия, время и версию проекта, без сырого списка прав сотрудников.

Миграция 20261111165153_company_project_readiness_audit.sql применена только к yaolkwbnhnacxxjpgiyu. Production/main и работающие сервисы не менялись.

## Фактическая проверка 11.11.2026

В production прочитаны только безопасные поля учётных записей (ID, имя, роль, активность, permissions) и справочника ЖК. Есть девять активных учётных записей, два ЖК с кодами 25601 и TOZON-PLAZA-2. Это подтверждает физическую связь Plaza/Plaza-2, но не полномочия директора, владельцев касс/складов и проектные назначения людей. Существующая ADMIN-роль, в том числе у тестовой учётной записи, не должна переноситься в новую модель как автоматически подтверждённое право компании. Рабочие права не изменены.

В тестовом реестре все пять партнёрских проектов ещё не имеют заполненных директора/основания, партнёров, назначений и постоянных привязок ЖК. Техническая проверка подтверждает это, а не сообщает ложную готовность. Активных Word-бланков и private bucket пока нет.

Проверки:

- 163 теста модулей проектов прошли, включая 10 новых проверок расчёта готовности/SQL и новую проверку HTTP-авторизации, чужого Origin, подмены actor и production URL.
- 32 теста интерфейса прошли. Проверены запуск по кнопке, отсутствие автоматических запросов/записи, поздний ответ другого проекта и запрет проверки несохранённых изменений.
- Сборка интерфейса с включёнными флагами успешна; oxlint изменённых компонентов без замечаний. Существующее предупреждение крупных chunks сохраняется.
- Настоящий SQL smoke выполнил прежние 28 команд, внутренние напоминания и новый аудит для двух проектов. Счётчики и состав ответа соответствовали только выбранному проекту; всё ROLLBACK.
- Контрольные суммы projects/users/deals совпали с исходными; постоянные назначения, команды, платежи/расходы и настройки напоминаний остались пустыми. Исходное общее уведомление сохранилось одно. Security advisors — только INFO.

## Данные для следующего шага

Для первого пилота Plaza нужны подтверждённые директор и основание подписи, второй партнёр и доли, список сотрудников и их проектные операции, собственные кассы/склады. В рабочей базе по похожему имени, городу или автору финансовой записи эти назначения не определять. Связи по кодам 25601 и TOZON-PLAZA-2 подготовлены, но production-перенос требует сверки денежных итогов и отдельного плана отката.

Настоящий HTTP Storage/браузерный прогон ещё не выполнен. Render-коннектор не выбрал рабочее пространство; для действий через него требуется подтверждённый workspaceId. Это не мешало проверкам кода и отдельной тестовой БД. Новый deploy или выбор рабочего пространства не выполнялись.
