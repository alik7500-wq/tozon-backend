# Себестоимость блоков по оплаченным РКО — V1

UI: `/finance/costs`, API: `/api/costs`. Доступ администратора либо отдельные `finance.costs` (чтение) и `finance.costs.write` (изменение). Другие финансовые/складские права не дают доступа к общему реестру затрат.

## Методика

Накопленные отнесённые на блок оплаченные расходы по РКО в USD / подтверждённая общая продаваемая площадь блока. Площадь включает квартиры и продаваемую коммерцию независимо от продажи. Общие коридоры и лестницы исключаются. Реестр помещений даёт подсказку, но автоматически не подтверждается: в текущей схеме нет достоверного разделения квартир/коммерции/непродаваемых помещений.

Это кассовый управленческий показатель. Неоплаченные обязательства, начисления, складские выдачи и авансовые отчёты не добавляются. Связанная проведённая выдача под отчёт исключается; её признанные расходы требуют отдельного будущего расширения источников. Прочие авансы/займы, не определяемые по данным, пользователь оставляет нераспределёнными или исключает с основанием.

- DIRECT: 100% выбранному блоку; SHARED: пропорционально подтверждённым площадям минимум двух блоков одного проекта; EXCLUDED: не является затратой; UNASSIGNED: требует решения.
- Общие доли сохраняют площади и версии оснований при назначении. Изменение базы обновляет знаменатель, но не перераспределяет старые РКО. Для этого нужно повторно распределить конкретный РКО.
- Включены операции по выбранную дату включительно. Площадь и назначения используются текущие; это не историческое воспроизведение прежнего состояния учёта.
- Сумма USD: `amount_minor / 100` для USD, для TJS — по положительному сохранённому курсу РКО, иначе положительный сохранённый `amount_usd`. Текущий банковский курс и извлечение суммы из комментария не используются. РКО без оценки в USD остаются видимыми и не входят в сумму.
- Служебная конвертационная нога, перевод между кассами, аннулированные/отменённые/сторнированные документы не входят в затраты. Реальный основной расход при автоконвертации учитывается один раз.
- Суммы распределяются в целых USD-центах методом наибольших остатков; равенство разрешается по ID блока. Расчёт пропорций выполняется BigInt.
- Изменение исходного РКО пересчитывает сумму; аннулирование исключает; удаление удаляет распределение по FK, история распределений сохраняется.

## Хранение и защита

Три самостоятельные таблицы `cost_building_bases`, `cost_expense_allocations`, `cost_audit`. Касса, расходы, платежи и строительный учёт миграцией не изменяются. На них нет новых триггеров. RLS включён на новых таблицах; anon/authenticated лишены доступа; сервер работает через service_role.

RPC `cost_save_basis` и `cost_save_allocation` — SECURITY INVOKER, пустой search_path, закрыты для публичных ролей. Проверяют действующего CRM-пользователя и отдельные права. Назначение, проверка версии и запись истории атомарны. Advisory lock сериализует изменения одной сущности. Optimistic version предотвращает потерю параллельных правок.

При создании РКО UI сначала сохраняет кассовый документ штатным API, затем отдельно назначает аналитическую принадлежность. Если второй запрос не прошёл, РКО остаётся сохранённым и попадает в нераспределённые; пользователю явно сообщается, что повторять кассовую операцию нельзя. Исходные кассовые алгоритмы не изменяются.

## Начало использования

1. «Финансы → Себестоимость блоков».
2. Подтвердить общую продаваемую площадь по проектной ведомости для каждого блока.
3. Распределить существующие РКО по документам; для общих выбрать SHARED. Не делать массового назначения по догадке.
4. В новых РКО указывать принадлежность сразу. Введённые через Telegram и другие источники РКО будут видны в нераспределённых.
5. Проверять очередь нераспределённых/без курса перед использованием показателя.
