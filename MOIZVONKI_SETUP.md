# Мои Звонки — первая интеграция

Документация: https://www.moizvonki.ru/guide/api/

В карточке клиента открывается вкладка «Звонки»: набор основного/дополнительного номера, история за 30 дней, направление, результат, длительность, сотрудник и запись при наличии. Используются calls.list и calls.make_call. SMS остаются в Payom.

## Серверные переменные Render

MOIZVONKI_ENABLED=true
MOIZVONKI_API_URL=https://YOUR-COMPANY.moizvonki.ru/api/v1
MOIZVONKI_API_KEY=<ключ из кабинета, только в серверном окружении>
MOIZVONKI_ADMIN_EMAIL=<email администратора сервиса>
MOIZVONKI_USER_MAP={"CRM_USER_ID":"manager@example.com"}

Карта сопоставляет ID пользователя TOZON и email пользователя Мои Звонки. Каждый сотрудник, включая руководителя, должен иметь явное сопоставление для исходящих звонков. Набор всегда идёт с его телефона, без подмены на телефон администратора.

Руководитель/администратор видит историю всех сотрудников через supervised=1; прочие пользователи видят только свою историю и только назначенных им клиентов, с правом leads.view или leads.manage. Набор требует leads.manage. Запросы ограничены 10 в минуту на IP. Ключ не передаётся клиенту, ответы провайдера об ошибках не выводятся.

## Проверка после выпуска

1. Настроить телефон и рабочую SIM, проверить оба голоса в записи на территории Таджикистана.
2. Настроить серверные переменные; без них интеграция сообщает, что не подключена.
3. Открыть клиент → Звонки → проверить историю и дополнительный номер.
4. Нажать Позвонить, подтвердить номер; проверить набор на нужном смартфоне. Команда не означает успешное соединение. При таймауте не повторять до проверки телефона.
5. Проверить входящий пропущенный, исходящий без ответа, ответ и запись.
6. Проверить отказ доступа к чужому клиенту под менеджером.

История загружается по запросу, без фонового опроса, с пагинацией до 50 страниц по 100 звонков. При превышении лимита показывается предупреждение, не утверждается полнота истории. События webhook, отдельный общий журнал пропущенных, задачи и ИИ в этот этап не входят. Новые таблицы и миграции не требуются. Реальный аккаунт и звонки не проверены без настроенных параметров.

Webhook-подписка пока не создаётся: API допускает только один обработчик на событие, новый URL заменяет предыдущий. Перед будущим подключением нужно проверить webhook.list и предусмотреть защищённый приёмник и хранение событий.

Отключение: MOIZVONKI_ENABLED=false. История и набор станут недоступны, данные CRM не изменяются.
