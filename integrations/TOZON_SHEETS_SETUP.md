# Подключение РКО из Telegram к Google Sheets

Код сервера сохраняет новые подтверждённые РКО в надёжной очереди. Исторические расходы не копируются. Две кассы сопоставлены по UUID CRM: Акмалхон и Илхомчон. Другие кассы получают статус UNMAPPED, без отправки в чужой лист.

## Однократное подключение владельцем таблицы

1. В оригинале «Сохтмони Автовокзал»: Расширения → Apps Script.
2. Вставьте содержимое `tozon-sheets.gs` в редактор.
3. Сервисы → плюс → Google Sheets API → Добавить.
4. Настройки проекта → Свойства скрипта: добавьте `TOZON_SHEETS_SECRET`, значение — случайный секрет минимум 32 символа. Не присылайте секрет в чат.
5. Развернуть → Новое развёртывание → Веб-приложение. Выполнять от своего имени, доступ «Все». Авторизуйте приложение. Каждая запись дополнительно проверяет подпись секретом; токены Google серверу CRM не передаются.
6. В Render, сервис tozon-backend → Environment, добавьте:
   - `TOZON_SHEETS_WEBHOOK_URL`: выданный Google URL веб-приложения, заканчивающийся `/exec`.
   - `TOZON_SHEETS_SECRET`: тот же секрет из свойств скрипта.
7. Сохраните переменные и дождитесь обновления сервера.

Новые РКО поступают в соответствующий лист после последней операции и до «ИТОГО». Форматы и выпадающие списки наследуются; остальные листы не изменяются. При заполнении участка вставляется строка перед итогами. Подпись запроса ограничена пятью минутами, обработка защищена блокировкой, сумма и метка идентификатора записываются атомарно. При сетевой ошибке сервер повторяет отправку с тем же идентификатором, без второй строки.

Столбцы: A дата, B получатель, C приход пустой, D расход USD, E статья, F номер РКО и назначение, G фактический курс, H отрицательная сумма TJS, I отрицательный эквивалент USD. Если фактический курс отсутствует, эквивалент другой валюты остаётся пустым. Текущий курс не подставляется: при расходе TJS без курса долларовый итог такого расхода не отражает.

Проверка после подключения: создайте реальный необходимый РКО в боте; проверьте строку, сумму и отсутствие дубля в таблице. Фиктивные расходы для проверки в production не создавайте. Очередь приватная, доступны только серверные операции service_role.
